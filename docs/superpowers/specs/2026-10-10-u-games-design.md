# U Games: личное приложение для Яндекс Игр

## Назначение

U Games — личный пет-проект для Android и iPhone. Приложение открывает
существующий сервис Яндекс Игры с его каталогом и игровыми страницами,
сохраняет возможность входа в Яндекс и исключает показ рекламы.

Если игра предлагает бонус за просмотр рекламы, пользователь нажимает
соответствующую кнопку и получает бонус без просмотра. Нового каталога,
собственных игр и отдельной системы аккаунтов в проекте нет.

## Согласованные требования

1. Поддерживать Android и iPhone.
2. Использовать сам сервис Яндекс Игры, а не похожий собственный сервис.
3. Открывать весь доступный пользователю каталог без ограничений по списку игр.
4. Исключать баннерную, полноэкранную и видео-рекламу, включая рекламу за награды.
5. Завершать обычные рекламные паузы без показа рекламы.
6. Выдавать предусмотренную игрой награду без просмотра рекламного видео.
7. Сохранять возможность входа и игрового прогресса через Яндекс.
8. Начать проверку с одной популярной игры, не ограничивая ею каталог.

## Объём первой версии

Две небольшие нативные оболочки: Android на Kotlin с WebView и iOS на Swift
с WKWebView. Обе используют общий JavaScript для рекламных вызовов и общий
набор правил блокировки ресурсов с платформенными адаптерами.

Приложение сохраняет каталог, поиск, карточки игр и игровой интерфейс
Яндекса. Нативная часть отвечает за загрузку, навигацию назад, повтор
загрузки при ошибке, сессию и жизненный цикл игрового окна. Дополнительные
экраны каталога не создаются.

Для первой версии предполагается работа с интернетом и личная установка
на устройства. Публикация в магазинах, офлайн-копии игр, собственная
монетизация, облачный сервер приложения и автоматическое скачивание
исполняемых правил не входят в эту версию. Эти границы уточняются при
рассмотрении спецификации, если они не соответствуют ожиданиям пользователя.

## Почему выбраны нативные оболочки

Нативные оболочки дают прямой доступ к раннему выполнению скриптов,
вложенным фреймам, сетевым фильтрам и хранению сессии каждой платформы.
Общий код сосредоточен там, где нужно одинаковое поведение: перехват
рекламных вызовов и правила фильтрации.

Альтернатива — Flutter с общей оболочкой. Она сокращает дублирование
элементов интерфейса, но всё равно требует проверить платформенные
возможности выбранного WebView-плагина. Для приложения с минимальным
собственным интерфейсом этот дополнительный слой не выбран.

## Компоненты и границы

### Android-оболочка

- Загружает каталог Яндекса и поддерживает переходы в игровые страницы.
- До загрузки устанавливает общий скрипт через document-start API WebView.
- Проверяет наличие поддержки раннего выполнения скриптов в установленном
  WebView; при отсутствии поддержки показывает понятную ошибку.
- Применяет сетевые правила средствами Android, сохраняя загрузку
  игровых ресурсов и вход в аккаунт.
- Сохраняет данные браузерной сессии между запусками.
- Передаёт кнопку «Назад» истории WebView, когда в ней есть предыдущая страница.

### iOS-оболочка

- Загружает те же страницы и общий скрипт через WKUserScript в начале документа.
- Выполняет скрипт в контексте страницы, включая вложенные фреймы.
- Использует постоянное хранилище данных WKWebView для сессии.
- Применяет правила блокировки ресурсов через WebKit content rules.
- Позволяет вернуться из игры в каталог и восстановить загрузку после ошибки.

### Общий рекламный адаптер

- Работает отдельно в каждом подходящем документе и фрейме.
- Учитывает, что SDK может появляться после начала загрузки страницы.
- Перехватывает подтверждённые рекламные точки входа провайдера Яндекса.
- Не вызывает исходный показ рекламы для перехваченного вызова.
- Для обычной рекламной паузы завершает вызов способом, который ожидает SDK.
- Для рекламы за награду отправляет предусмотренный SDK сигнал о награде,
  затем сигнал завершения, в порядке, подтверждённом реальной интеграцией.
- Не выдаёт награду дважды при повторной установке адаптера или повторном
  завершении одного рекламного запроса.
- Сохраняет остальные функции SDK: авторизацию, сохранения и игровое состояние.

SDK-вызовы и точные точки перехвата определяются по наблюдаемой интеграции.
Документация не считается доказательством доступности объекта SDK для
подмены во всех играх. Адаптер не должен подменять весь SDK пустым объектом.

### Фильтр ресурсов

Содержит конкретные рекламные правила, подтверждённые наблюдением.
Он дополняет перехват SDK, но не заменяет корректное завершение рекламного
сценария. Широкая блокировка всех ресурсов Яндекса недопустима: те же
страницы используют игровые, авторизационные и служебные ресурсы.

Общий источник правил преобразуется в платформенные форматы.
Он хранится в репозитории и поставляется вместе с приложением.

## Основные сценарии

### Каталог и запуск игры

Пользователь открывает приложение, видит каталог Яндекс Игр и запускает
любую доступную игру. Оболочка устанавливает адаптер до выполнения кода
страницы, в том числе в игровых фреймах. Игра загружает свои обычные ресурсы.

### Рекламная пауза

Игра вызывает рекламный API. Адаптер завершает рекламный сценарий без
показа. После этого игра продолжает работу. Отдельное видео или рекламное
окно не открывается.

### Награда

Пользователь нажимает существующую кнопку бонуса в игре. Адаптер выдаёт
сигнал о награде и завершает сценарий без рекламного просмотра. Награду
применяет сама игра. Переписывание игрового баланса или серверных ответов
не является запасным способом реализации.

### Вход и прогресс

Пользователь входит через существующий интерфейс Яндекса. Оболочка
поддерживает необходимые переходы и окна входа, не собирает пароль
самостоятельно и сохраняет сессию в штатном хранилище WebView.
Сохранения и синхронизацию выполняет сервис и конкретная игра.

## Ошибки и жизненный цикл

- При отсутствии сети или ошибке загрузки показывать сообщение с повтором.
- При возврате из фона не запускать повторный рекламный запрос и не выдавать
  повторную награду от уже завершённого вызова.
- Новое игровое окно получает тот же адаптер и фильтры; переход не должен
  создавать незащищённое игровое окно.
- При выявленной несовместимости адаптера показывать ошибку вместо
  намеренного включения рекламы как запасного режима.
- Данные диагностики описывают загрузку адаптера и рекламные вызовы,
  исключая пароли, cookies и содержимое сохранений.

## Проверка технической осуществимости

До расширения реализации необходимо проверить на реальном сервисе:

1. Где создаётся SDK и доступны ли рекламные точки входа для перехвата.
2. Какие фреймы и источники документов участвуют в запуске игры.
3. Отсутствие рекламы при старте и во время игры после вмешательства.
4. Продолжение игры после обычной рекламной паузы.
5. Выдачу одной награды по одному пользовательскому запросу без видео.
6. Работу входа, сохранения сессии и прогресса после перезапуска.

Первый кандидат — «Мир домовят», найденная в официальной подборке популярных
игр. Она использует внешний игровой фрейм и поддерживает авторизацию и
облачные сохранения. Наличие в ней сценария рекламы за награду пока не
подтверждено. Если такого сценария нет, для его проверки выбирается ещё
одна игра из того же каталога.

Результат этого этапа — наблюдаемый механизм перехвата либо конкретное
техническое препятствие. При препятствии архитектура пересматривается
с пользователем; обещание совместимости не заменяет проверку.

## Проверки и критерии приёмки

### Автоматические проверки общего адаптера

- Позднее появление SDK и повторная установка адаптера.
- Завершение обычной рекламной паузы без вызова исходного показа.
- Ровно одна выдача награды и одно завершение запроса.
- Отсутствие влияния на нерекламные методы SDK.
- Обработка вложенных документов и повторного открытия игры.

### Проверки на обеих платформах

- Сборка и запуск оболочки.
- Каталог и запуск выбранной игры без рекламных баннеров и окон.
- Обычная рекламная пауза без показа и зависания игры.
- Бонус за рекламу без видео, с фактическим изменением состояния игры.
- Вход в Яндекс и сохранение сессии после закрытия приложения.
- Сохранение доступного игре прогресса после перезапуска.
- Навигация назад, восстановление из фона и повтор после сетевой ошибки.

Доступность всего каталога — требование к отсутствию искусственного
ограничения игр. Она не равнозначна доказанной совместимости каждой игры.
Отчёт о проверках перечисляет фактически проверенные игры, устройства и
сценарии. После успешного первого сценария проверяется несколько игр с
разными рекламными механиками и размещением; сам каталог остаётся полным.

## Известные технические ограничения

Раннее выполнение скрипта поддерживается платформенными API, но не
гарантирует доступность и стабильность внутренних объектов сервиса.
Изменение SDK Яндекса может потребовать обновления приложения.
Блокировка сети сама по себе не подтверждает отсутствие всех видов рекламы
и не гарантирует завершение игрового сценария.

Выдача клиентского сигнала о награде не доказывает, что любая игра примет
его: отдельная игра может проверять награду на сервере. Этот случай
проверяется наблюдением и явно фиксируется как несовместимость, если
согласованный механизм не работает.
