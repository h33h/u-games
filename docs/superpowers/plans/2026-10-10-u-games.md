# U Games Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Личное приложение для Android и iPhone, открывающее весь каталог Яндекс Игр без рекламы, с входом в аккаунт и выдачей наград без видео.

**Architecture:** Тонкие нативные оболочки WebView и WKWebView используют общий JavaScript и общий источник правил фильтрации. Перехват рекламных вызовов завершает игровой сценарий, а фильтры препятствуют загрузке рекламных ресурсов. Проверка живого SDK предшествует реализации адаптера; проверка в браузере не заменяет приёмку на обеих платформах.

**Tech Stack:** Kotlin, Android WebView, AndroidX WebKit; Swift, UIKit, WKWebView; JavaScript и встроенный Node.js test runner; Gradle Wrapper и XcodeGen.

**Spec:** [2026-10-10-u-games-design.md](../specs/2026-10-10-u-games-design.md).

## Global Constraints

- Поддерживать Android и iPhone.
- Использовать сам сервис Яндекс Игры, а не похожий собственный сервис.
- Открывать весь доступный пользователю каталог без ограничений по списку игр.
- Исключать баннерную, полноэкранную и видео-рекламу, включая рекламу за награды.
- Завершать обычные рекламные паузы без показа рекламы.
- Выдавать предусмотренную игрой награду без просмотра рекламного видео.
- Сохранять возможность входа и игрового прогресса через Яндекс.
- Начать проверку с одной популярной игры, не ограничивая ею каталог.
- Общие скрипт и правила поставляются с приложением; облачный сервер и удалённое обновление исполняемого кода не нужны.
- Диагностика исключает пароли, cookies и содержимое сохранений.
- Несовместимость не включает рекламу как запасной режим.

## Review Focus

1. SDK появляется поздно или повторно: перехват действует до рекламного вызова, нерекламные функции сохраняются — Task 2.
2. Callback игры выбрасывает исключение: завершение рекламного сценария всё равно выполняется один раз — Task 2.
3. Внешний iframe или новое окно игры: тот же адаптер работает в новом документе — Tasks 4–5.
4. Сбой рендерера или уход в фон: восстановление не создаёт повторную награду — Tasks 4–5.
5. Фильтр совпадает с похожим доменом или страницей входа: ресурсы игры и авторизации не блокируются — Task 3.

## Выбор инструментов для реализации

- Android: AGP `9.4.0`, Gradle `9.6.0`, JDK `17`, AndroidX WebKit `1.17.1`, `compileSdk = 36`, `targetSdk = 36`, `minSdk = 24`. Использовать встроенную поддержку Kotlin в AGP; не добавлять второй Kotlin Android plugin.
- iOS: deployment target `15.0`, UIKit и WebKit без внешних runtime-зависимостей; схема `UGames`. XcodeGen уже доступен локально.
- Node.js: доступный Node `20.20.2`, `node:test`, `node:assert/strict`, `node:vm`.
- Идентификатор Android: `dev.ugames`; базовый bundle identifier iOS: `dev.ugames.app`. Подписывающая команда Apple выбирается локально при установке на устройство и не записывается как общий секрет.
- Не менять Java по умолчанию в системе; передавать путь к JDK 17 в окружении Android-сборки. Искать существующий Android SDK вне стандартного каталога прежде, чем устанавливать новый.
- Точные версии Android выбраны по [AGP compatibility](https://developer.android.com/build/releases/agp-9-4-0-release-notes) и [AndroidX WebKit releases](https://developer.android.com/jetpack/androidx/releases/webkit). Перед скачиванием проверить доступность артефактов в официальных репозиториях; при расхождении записать совместимый набор в отчёт и build-файлы.

### Task 2: Реализовать общий адаптер рекламных вызовов

**Files:** Create `shared/ad-adapter.js`, `shared/tests/ad-adapter.test.cjs`, `shared/fixtures/sdk-lifecycle.html`, `shared/fixtures/frame.html`, `package.json`, `.gitignore`.

**Interfaces:**
- Consumes: подтверждённые методы и lifecycle из Task 1.
- Produces: самодостаточный IIFE, выполняемый на document-start в каждом фрейме. Внутренние функции `installInWindow(win)`, `patchSdk(sdk)`, `completeFullscreen(options)`, `completeRewarded(options)`; повторная установка идемпотентна. Для диагностики доступен `window.__UGamesAdapter = {version, status, intercepted}` с числовыми счётчиками, без данных пользователя.

- [ ] **Step 1:** Написать тесты в изолированных `node:vm` контекстах: SDK отсутствует при старте и появляется позже; повторный `init` возвращает новый объект; нерекламный `getPlayer()` сохраняет результат; оригинальные рекламные методы не вызываются.
- [ ] **Step 2:** Добавить проверки callback-порядка. Для fullscreen: `onClose(false)` ровно один раз без исходного показа. Для rewarded: `onOpen`, `onRewarded`, `onClose(true)` по одному разу, асинхронно относительно пользовательского вызова. `true` означает завершённый виртуальный rewarded-сценарий для совместимости, а не фактический показ видео; подтвердить этот выбор наблюдениями Task 1. Отдельно проверить исключение из `onRewarded`: `onClose` всё равно выполняется. У повторных пользовательских запросов отдельные награды, у повторной инъекции нет дополнительных наград.

  Основные assertions после завершения асинхронного запроса:
  ```js
  assert.equal(originalAdCalls, 0);
  assert.deepEqual(fullscreenEvents, [['close', false]]);
  assert.deepEqual(rewardedEvents, [['open'], ['reward'], ['close', true]]);
  assert.equal(playerAfterPatch, playerBeforePatch);
  ```

## Исполнение

Рекомендуемый способ — последовательно в текущей сессии: задачи зависят от
наблюдений реального SDK и общего адаптера, поэтому параллельная реализация
до подтверждения этих интерфейсов не приносит пользы. После реализации
провести одно независимое ревью всего изменения. Альтернатива — отдельный
исполнитель и ревьюер для каждой задачи после согласования плана.

До продуктового кода пользователь рассматривает этот план и выбирает способ
исполнения. Рабочая изоляция создаётся через using-git-worktrees при начале
реализации, а не в ходе подготовки документа.
